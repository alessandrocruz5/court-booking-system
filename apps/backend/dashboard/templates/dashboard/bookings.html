{% extends "dashboard/base.html" %} {% comment %} The bookings list: a toolbar, a count, and the results (a table on desktop, cards on a phone). All of the list's state lives in the URL (q, status, sport, source, from, to, sort, page), so the toolbar is a plain GET form that works without JS (the status segments are radios, applied with the Apply button); htmx only swaps the `results` partial in and pushes the URL. Every value arrives from `dashboard.queries`, already masked for the viewer's role, and every URL parameter was validated by `parse_list_params`. A row is one link to the booking, carrying the list's current query string, so the detail page's back link restores the list as it was. The status pill uses `status_key` (the derived status: block, completed, checked_in or the stored one), which has a CSS class but no label of its own, hence the label chain below.
